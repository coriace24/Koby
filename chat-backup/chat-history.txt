what git pull does?

----- CLAUDE  (2026-07-23 23:28 UTC) -----
`git pull` means: **"download the latest changes from GitHub and apply them to the copy on this machine."**

The mental model: your project exists in three places right now —

1. **GitHub** (the shared original — where I just pushed the calculator/settings update)
2. **Your Codespace's copy**
3. **Your Windows PC's copy**

The copies don't update themselves. When new commits land on GitHub — because I pushed, or because you pushed from another machine — each copy stays as it was until you run `git pull` in it. Git then fetches the new commits and updates your files to match. It's the receiving counterpart of `git push`:

- `git push` = send *my* commits up to GitHub
- `git pull` = bring GitHub's commits down to *me*

A few practical notes for your situation:

- Running it is safe: it only touches files tracked by git. Your `.env`, database (`dev.db`), and uploaded documents are ignored by git, so a pull never disturbs your API key or your data.
- If there's nothing new, it just says "Already up to date." Running it "too often" costs nothing.
- If you edited a file locally *and* the same file changed on GitHub, git will ask you to reconcile rather than overwrite you — that's the merge situation I mentioned before, avoided by the habit **pull when you sit down, push when you finish**.
- After *this particular* pull, remember the one extra step: `npx prisma@6.19.3 db push`, because the update added new database fields (asking price, closing costs, unit mix, settings). Then `npm run dev` as usual.
